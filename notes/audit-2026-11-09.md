## Verdict

serviceman does what it says for the owner who is alone on trusted machines: 541 tests pass, the
linter is clean, the tokens and their rights hold on every route tried, paths stay inside their
folders, an app folder's `data/` survived every hostile zip, and a restart of the agent or of
serviceman loses nothing it started. The risk is in three places.

**One message stops a whole process.** No program here has a last net, and several handlers
throw outside any promise. One handshake with no token stops serviceman (SM-168), and so do six
bytes at a shell (SM-170), one hello from a machine (SM-199), one forward's label (SM-200) and
one line that is not JSON (SM-240); one request stops web-terminal (SM-282), one reset an agent
(SM-215). Each is a line or two to mend, and there are about fifteen of them.

**A machine is trusted more than the threat model says.** A machine whose agent is hostile can
stop the host with one hello, fill its memory, write files on its neighbours through a copy,
forge the host's log, and blank the control page; in the other direction, whoever answers an
agent's dial over plain http owns that machine and can wipe it.

**The page and the docs have drifted from the code.** Saving a card silently drops fields the
form does not know; eight config examples of the docs are refused, the first of them stops
serviceman at its start; and several passages (what the token buys, what serviceman never
deletes, how a program outlives the agent) describe an older system.

### SM-168 One handshake with no token stops serviceman (critical)
Where: `src/main/src/routes/handle_control_upgrade.js:36`, called bare from
`src/main/src/helpers/server_start.js:65` (the service port, when the Host is the control name)
and `:110` (the control port).

Evidence: the handler's first line is `const url = new URL(req.url, 'http://serviceman.invalid');`,
before any check, and both `out.on('upgrade', …)` handlers call it with nothing to catch a throw.
A request target of `//` makes `new URL` throw. Driven on a scratch serviceman (services on
4100, control on 4101), one raw request on the **service** port, no token:

    GET // HTTP/1.1
    Host: serviceman.localhost
    Connection: Upgrade
    Upgrade: websocket

    before: control answers 401
    after: control answers 000
    code: 'ERR_INVALID_URL', input: '//', base: 'http://serviceman.invalid'
    serviceman exited with 1

The same handshake under a service's name (`Host: echo.localhost`) is survived: that path
(`handle_upgrade`) is a promise with a `.catch`.

service reaches, stops the whole host: every service it fronts and every machine's link. The
control name is the default one and is in the docs. No token, no sign-in.

Mend: parse the address inside a `try` and destroy the socket; or wrap both `upgrade` handlers
as the request path's `answer()` is wrapped. See also the three findings of the same kind:
web-terminal, module-host, and a frame at a shell.

### SM-350 A service that answers with a status no HTTP has stops serviceman, and the agent that proxies it (high)
Where: `src/main/src/proxy_request.js:35` (`res.writeHead(proxy_res.statusCode, …)` inside the
answer's callback), `src/agent/src/agent_door_proxy.js:25`
(`res.writeHead(answer.statusCode, answer.statusMessage, raw)`, the same place in the agent).

Evidence: Node's client takes `HTTP/1.1 099 Odd` and `HTTP/1.1 000 Zero` as statuses 99 and 0,
and `writeHead` refuses both: `RangeError [ERR_HTTP_INVALID_STATUS_CODE]: Invalid status code:
99`, thrown in a callback nothing catches. A scratch serviceman with one `external` service
answering `HTTP/1.1 099`: the process exits with 1 at `proxy_request.js:35:21`. An agent with a
stand-in service behind its door: `agent alive: false exit 1`. The agent passes the status words
on too, and words with a control byte end it the same way (`ERR_INVALID_CHAR`); statuses 999, bad
headers, a reset and a body cut short left both alive.

Consequence: any service serviceman fronts, a hostile image among them, takes the host down with
one answer, and every other service with it; behind a machine's door, that machine's agent.

Mend: a status outside 100 to 999, or words `writeHead` refuses, is a 502 for that visitor, as an
upstream that cannot be reached is; the same in the agent.

### SM-351 A link planted by one copy of a folder is written through by the next (high)
Where: `modules/file_manager/server/transfer_queue.js:471` (links are made last, as the walk
names them: a target may point anywhere, by design), with the disk written to made without a
root (`src/main/src/routes/handle_control_request.js`, `remote_disk(app, remote)` for a copy).

Evidence, with SM-239's mend in place: two copies of the same folder into the same place, from a
machine whose agent lies. The first walk names the link `lib -> <scratch>/outside`, the second
the file `lib/evil.txt`, a legal path: `the second copy: phase=ok`, and `on desktop, under
outside/: ["evil.txt"]`.

Consequence: what SM-239 closed in one copy stays open across two: the machine copied from
writes where its neighbour's agent may, outside the folder copied into.

Mend: the machine copied to keeps the copy within the folder copied into, links too, as an
agent's token is kept within its folders (`root`); an owner's own link in the destination that
leads out is then refused, and said.

### SM-352 A folder copied by tar may land names beside the folder (high)
Where: `modules/file_manager/server/transfer_queue.js:540`, `:560`
(`to.write_tar(item.to.dir, …)`): the tar's names are held under the folder copied into, not
under `<dir>/<name>`.

Evidence, with SM-239's mend in place and an honest walk: a source whose tar carries
`sibling.txt`: `phase=ok … files=1`, and `on desktop, under dest/: ["in/", "in/folder/",
"in/sibling.txt"]`.

Consequence: a copy into a home folder could carry `.ssh/authorized_keys` this way.

Mend: hold each name of the tar to `<name>/…` as it passes, or have the tar made from the folder
itself into `<dir>/<name>`.

### SM-353 The three demo servers open a websocket to any page, with no token (medium)
Where: `demos/terminal-web/server.js:45`, `demos/terminal-web-ssh/server.js:58`,
`demos/files-web/server.js:63`; they lend `SERVICEMAN_TOKEN` to whoever asks
(`demos/terminal-web/server.js:136`) and have no door of their own, `POST /end` included (`:121`).

Evidence: each answered `HTTP/1.1 101 Switching Protocols` to a handshake with `Origin:
https://blog.example.com` and no token or cookie (their `URL` pointed at nothing, so no terminal
was reached). They listen on the loopback.

Consequence: with a demo running, any page open in the same browser reaches the terminal or the
files it fronts with the demo's own token.

Mend: the page's own origin and a key in the page's address, as module-host has; an Origin check
alone would not mend them.

### SM-354 web-terminal's image lacks a helper its terminal module requires (medium)

### SM-355 The agent's program follower writes from a timer with nothing to catch a throw (medium)

## What is good

What the readers tried to break and could not; it is to be kept as it is.

- **Tokens and rights.** Every scoped token got 403 everywhere but its own right; a token for
  one machine could not reach another; the owner-only doors refused every scoped token; tokens
  are compared hashed and in constant time; a foreign Host is 404, a write from another site
  403, a body above the limit 413.
- **Paths.** `../`, encoded and double-encoded, backslashes and null bytes got nothing outside
  the static, skin and module folders; with a token's root, `..`, an absolute path and a path
  through a link out were refused by the agent for reads, stats and tar both ways; tar names
  `../x` and `/x` are refused before the disk is asked, and a name shaped like an option goes to
  tar as `./…`.
- **An app folder's `data/`.** A zip's `data/` in every place and spelling never reached the
  app's own; a key file was the same, byte for byte, after eight versions; hostile zips (`../`,
  absolute paths, links, a size that lies) were refused before anything was sent; a `kill -9`
  mid-zip left the app running.
- **Restarts lose nothing.** `kill -TERM` and `kill -9` of the agent: the program, the kept
  terminal and its shell lived on and were found again; after SIGTERM or `kill -9` of serviceman
  what still ran was adopted and nothing started twice.
- **Pools and idle stops.** 40 requests at once on `concurrency: 2, max: 4` gave four copies,
  never more than two in flight each; 168 requests timed around seven idle stops were all 200.
- **The pages.** No raw-HTML sink takes text of a machine, a config or a URL in any page; every
  name in a request path is encoded; the token is HttpOnly and SameSite=Strict, never in the
  address or in storage; 172 page loads drew with no script error; storage that throws breaks
  nothing; an empty serviceman says on each page what is missing.
- **Secrets and modes.** No token appeared in any log a reader produced; a volume's key goes to
  cryptsetup on stdin alone and a shared folder's secrets through the environment alone; the
  agent's sockets, token, door table and secrets are 0600 in 0700 folders; the root half
  verifies the same bytes it then writes.
- **Arguments.** ufw, du, apt and the in-container commands are run by argv with `--` before
  names, with no shell and no word from the link in apt's lines.
- **Logline's door.** No token, a wrong one, the admin token at `/lines`, a machine's token at
  the admin doors and a token from another address are refused before the body is read; a
  batch's `remote` is set from the token; the queries take values as parameters alone.
- **The build's files.** The ten vendored files equal `node_modules` at the lock's versions byte
  for byte; the agent bundle says 1.33.0 and its fingerprint equals `version.json`; the 22
  committed pages of the site equal a fresh `bin/build-pages`; all 153 links, anchors and
  pictures of the docs resolve.
- **The discipline.** The agent's version was raised in every commit that changed the agent;
  each of the 18 commits since 1.0.1 raised the version and wrote its changelog line; all but 16
  of 529 server files are loaded in some test's process.
